## 使用
1. 克隆本项目：

   git clone <https://github.com/Gust-feng/hnsoft>

2. 配置 `.env` 文件：

3. 安装依赖：

### 为什么有了本项目
之前学校的课程小助手会在每晚通过微信提醒第二日课程，此前一直为不觉得有多重要，直到年后小助手似乎一病不起，似乎服务器因为某种原因停了，导致现在想看课表需要登陆学校的网站才能查看，这样总归麻烦了点，可遗憾的是，并没有人愿意每天登录教务系统查看课表，即便上课上久后记着这些课程的上课时间，但频繁的调课经常扰乱这种上课顺序，所以能不能自己研究研究，爬取自己的课表，并每日更新？

### 一些闲言碎语
我第一时间想到学校的教务系统，教务系统采用 SSO 单点登录，当登录成功后获取到cookie可以携带 Cookie 通过 GET 请求获取当周的课表，无需加载所有网页，无疑这样对学校服务器压力最小，单次请求一次学校的课表信息仅有10kb左右，和正常访问相比，其数据量微乎其微，但当我真正尝试构建一套完整流程时着实遇到了不少问题

我首先注意到整个流程是明文传输的，但请求体参数中包含很长一串处账号密码以外的字符，是的，在使用http协议下继续加密了一次...

~~虽然使用http加密但本人实力还不足以完全分析并复现整个浏览器发起的关键请求~~，最难的不是反爬机制，而是防重放和加密。防爬机制做的不算高明，验证码可以使用[ddddocr](https://github.com/sml2h3/ddddocr)轻松通过并且通过率几乎100%，在初次访问网站时会返回初始cookie，Execution ID 和随机盐，对于正常使用浏览器登录的用户完全无需考虑这些东西，因为浏览器在背后默默记录这些东西，用户只要填写表单，提交，程序就会如期进行。现在我需要模拟浏览器并提交http请求获取服务器返回的正确cookie，我首先注意到整个流程是明文传输的，但请求体参数中包含很长一串处账号密码以外的字符，里面包含随机盐和Execution ID，理论上来说，每次GET 网站可以获得这两个值，密码使用自己的，公钥也是公开的，只需要截取http中的加密字段便可尝试复现加密方式。是的，理论上是这样的。

奈何学艺不精，获取公钥后，我截取到同一个会话的随机盐和base64密文尝试将自己密码和随机盐复现base64密文后悻悻而归，我现在并不能解密这样方式的加密。

 ### 转机
 当我无计可施时，突然意识到课表似乎并不只在教务系统有！

是的，我在小助手中找到一篇公众号，里面的二维码指向学校服务器的IP，并且可以登录查看课表。
庆幸的是这个网址的请求比教务系统那个简洁不知多少，通过多次抓包发现密文固定，除此以外并没有其他随机盐进行加密措施,也就意味着当密码不改，HTTP 请求是固定的。
于是便有了本项目...
